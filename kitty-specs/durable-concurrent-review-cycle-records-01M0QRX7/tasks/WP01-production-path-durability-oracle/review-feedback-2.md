## Failure cluster 1 — fake or wrong-surface router success

Several positive matrix cells inject a router that reports `committed` at the
literal ref `primary` without placing the exact evidence bytes at the governed
destination. WP03 verifies the governed ref and reports
`persistence_failed/destination_readback_missing`; WP04 correctly turns that
outcome into exit 1 instead of allowing event emission.

Required correction:

1. Positive automatic cells must use a real router or a faithful governed-ref
   fixture that commits the exact generated bytes to the placement-selected
   destination.
2. A router that returns `committed` without exact destination bytes is a
   negative control and must assert a nonzero typed persistence failure, no
   authoritative verdict event, and no durability claim.
3. Do not replace exact `git show` byte comparison with working-tree existence,
   substring checks, a clean-status check, or trust in
   `verdict_durably_persisted`.

## Failure cluster 2 — protected and neutered automatic paths

Protected-destination cells and commit-removal/neutered-router controls still
expect `_do_move_task()` to proceed far enough for later assertions. The final
contract requires automatic evidence failure to stop before the status event.

Required correction:

- assert the command's nonzero exit or `VerdictPersistenceFailure` envelope;
- require `durability_classification=persistence_failed`;
- require the exact stable reason appropriate to the injected cause, retained
  evidence path when one exists, and `verdict_durably_persisted=false`;
- prove no success event was emitted; and
- keep the commit-router-unreachable assertion for protected paths.

Do not catch the error merely to turn the old success expectation green. The
failure itself and its causal fields are the intended assertion.

## Failure cluster 3 — evidence-mutant envelope drift

`test_sc004_evidence_commit_mutant_reports_missing_committed_evidence` receives
the correct production refusal:

```text
result=error
verdict_durably_persisted=false
durability_classification=persistence_failed
durability_reason=destination_readback_missing
evidence_ref=<review-cycle path>
destination_ref=<governed ref>
```

The WP01 helper `_sc004_refusal_kind()` only accepts an obsolete nested
`cause=missing_committed_evidence`, so it misclassifies this fail-closed result
as `unproven_refusal`.

Required correction:

1. Parse the canonical production envelope rather than inventing a second error
   schema.
2. Recognize only the exact top-level `persistence_failed` plus
   `destination_readback_missing` combination for this mutant.
3. Continue to require nonzero exit, no durability claim, a stable evidence
   pointer, the governed destination, no correlated authoritative verdict
   event, and independent absence of exact bytes at that destination.
4. Map that proven production refusal to the oracle's logical
   `missing_committed_evidence` result.
5. Keep negative controls for malformed, broad-text, wrong-reason, exit-zero,
   and event-present responses.

Do not rename or weaken the production reason merely to fit the stale test
parser. The mission data model requires `persistence_failed` with an explicit
reason; WP03's exact read-back reason is the authoritative one.

## Failure cluster 4 — identical retained-record adoption

`test_sigkill_between_write_and_commit_then_identical_retry_exits_zero` asserts
that an identical retry allocates a different cycle path. WP03 commit
`3ca64f2116` deliberately implements
`_adopt_or_allocate_review_cycle_locked()`: an identical retry adopts the exact
retained pending record and commits it instead of stranding it and allocating a
duplicate. That is the locked mission decision documented in `research.md`.

Required correction:

- assert the retry returns the same artifact path and cycle number;
- assert its exact bytes become committed at the governed destination;
- assert no duplicate review-cycle artifact is allocated;
- assert the retry completes durably and the current verdict references that
  adopted evidence; and
- include a non-identical retry control that still allocates separately or
  refuses according to the production contract.

Do not revert WP03's adoption behavior and do not loosen identity matching.
