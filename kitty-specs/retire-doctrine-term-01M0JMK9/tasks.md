# Work Packages: Retire the Doctrine Term

**Inputs**: Design documents from `kitty-specs/retire-doctrine-term-01M0JMK9/`
**Prerequisites**: plan.md (required), spec.md (user stories), research.md, data-model.md, contracts/, quickstart.md

**Tests**: Planning-only C-001 permits required docs-contract CI metadata. Verification includes
contract round-trip/ratchet tests, terminology guard, ADR freshness, content+pathname audit arithmetic,
and one named independent review pass.

**Organization**: Fine-grained subtasks (`Txxx`) roll up into work packages (`WPxx`). Each work
package must be independently deliverable and testable. The plan's Parallel Work Analysis fixes a
**single stream**: the four deliverables are sequentially dependent (ADR → inventory → methodology →
stacked plan), so WPs form one dependency chain with no parallel lanes.

**Prompt Files**: Each work package references a matching prompt file in `/tasks/` generated by
`/spec-kitty.tasks`. Treat this file as the high-level checklist; keep deep implementation detail
inside the prompt files.

## Subtask Format: `[Txxx] [P?] Description`

- **[P]** indicates the subtask can proceed in parallel (different files/components).
- Include precise file paths or modules.
- Subtasks are **reference rows**, not checkboxes: record completion with `spec-kitty agent tasks mark-status <Txxx> --status done`. The reduced event-log snapshot is the sole subtask-completion authority — there is no `- [ ]` box to tick.

## Path Conventions

- **Mission artifacts** (deliverables): `kitty-specs/retire-doctrine-term-01M0JMK9/`
  (`implementation-baseline.json`, `inventory.md`, `inventory-hits.tsv`, `methodology.md`, `stacked-plan.md`, `verification-report.md`)

  (status frontmatter only — C-003 carve-out)

  `research.md` (R1–R16 resolved unknowns), `quickstart.md` (verification runbook)
- No product `src/` or agent-directory changes. Docs-contract skip metadata and ratchet baseline are
  allowed planning-CI edits (C-001).

## Work Package WP02: Occurrence Inventory — Mechanical Audit (Priority: P0)

**Goal**: Produce `inventory.md` plus one-row-per-hit `inventory-hits.tsv` from pinned content and
pathname audits, with stable OC-## classes over S1–S10, X1/X2/X3 classification, zero unclassified,
and owner-complete out-of-repo deferrals.
**Independent Test**: The NFR-001 mechanical audit re-run finds 0 unclassified user-facing
occurrences; the completeness statement's arithmetic holds (SC-002).
**Prompt**: `/tasks/WP02-occurrence-inventory.md`
**Requirement Refs**: FR-006, FR-007, NFR-001, C-003, C-005

### Included Subtasks

T005 Pin `base_commit`; run the contract's `git grep -aino --column` all-blob audit and NUL-safe `git ls-tree -z` pathname audit verbatim
T006 Build deterministic `inventory-hits.tsv`; classify every row into OC-## over S1–S10 or X1/X2/X3, including all operator IDs, serialized config, overlays, glossary authorities/referrers, overrides, workflow pathnames, active human prose under source directories, supported public APIs, exact `doctrine.api.__all__`, and distribution/wheel metadata
T007 Derive OC and X totals mechanically from manifest rows; verify no duplicate/unclassified coordinates and compute manifest SHA-256
T008 Write `inventory.md` per contract; include arithmetic and owner/milestone/tracking-complete out-of-repo deferrals; assignment remains solely in `stacked-plan.md`

### Implementation Notes

- Audit **first**, classify second. Every textual match and matching pathname has a manifest row;
  per-file totals and representative examples are never classification evidence.
- Per-hit scope rule (`data-model.md` §3 OC-I2): user-facing strings inside `src/` are in scope
  (S1/S3/S4/S7 as their audience/role requires);
  only non-public internal code identifiers are X1. Operator IDs, public Python names/imports
  (`__all__`, package re-exports, public docs/skills, external contracts), exact
  `doctrine.api.__all__`, and installable distribution/project/wheel metadata are OC even when they
  live inside `src/doctrine/`.
- Glossary authorities are `docs/context/doctrine.md`, `.kittify/glossaries/spec_kitty_core.yaml`,
  and the built-in glossary pack; none is X3. Mission artifacts become X2 at merge whether or not
  later archived; active/unmerged mission artifacts are never X2.
- `assigned_mission` is absent from inventory. WP04 is the single assignment owner.

### Parallel Opportunities

None — classification (T006/T007) consumes the raw audit record (T005); the artifact write (T008)
consumes both.

### Dependencies

- Depends on WP01 — classification rules cite the ADR's scope decisions, especially the
  operator-typed identifier split (IC-02 sequencing in plan.md).

### Risks & Mitigations

- **Completeness circularity (NFR-001)** → manifest-row count must exactly equal content occurrence
  plus pathname outputs; stable coordinates make every classification independently recoverable.
- **Misclassification of `src/` (path-level vs string-level)** → OC-I2 is applied per occurrence
  string; the prompt carries the S7 example (`src/charter/context_renderers/bootstrap_text.py`
  "Action Doctrine" heading) as the worked case.
- **Count drift from concurrent catfooding** → the inventory-schema per-wave contract requires
  `base_commit` in frontmatter; drift is recorded and re-baselined per wave, not silently absorbed.
