# Work Packages: Retire the Doctrine Term

**Inputs**: Design documents from `kitty-specs/retire-doctrine-term-01M0JMK9/`
**Prerequisites**: plan.md (required), spec.md (user stories), research.md, data-model.md, contracts/, quickstart.md

**Tests**: This mission is docs-only (C-001) — no new tests are written. Verification is the
`quickstart.md` runbook (guard green, `freshen_adr_inventory --check`, mechanical-audit arithmetic)
plus named independent review passes. Each WP's prompt names its targeted verification surface so a
reviewer can confirm scope (charter Testing Requirements).

**Organization**: Fine-grained subtasks (`Txxx`) roll up into work packages (`WPxx`). Each work
package must be independently deliverable and testable. The plan's Parallel Work Analysis fixes a
**single stream**: the four deliverables are sequentially dependent (ADR → inventory → methodology →
stacked plan), so WPs form one dependency chain with no parallel lanes.

**Prompt Files**: Each work package references a matching prompt file in `/tasks/` generated by
`/spec-kitty.tasks`. Treat this file as the high-level checklist; keep deep implementation detail
inside the prompt files.

## Subtask Format: `[Txxx] [P?] Description`

- **[P]** indicates the subtask can proceed in parallel (different files/components).
- Include precise file paths or modules.
- Subtasks are **reference rows**, not checkboxes: record completion with `spec-kitty agent tasks mark-status <Txxx> --status done`. The reduced event-log snapshot is the sole subtask-completion authority — there is no `- [ ]` box to tick.

## Path Conventions

- **Mission artifacts** (deliverables): `kitty-specs/retire-doctrine-term-01M0JMK9/`
  (`inventory.md`, `methodology.md`, `stacked-plan.md`, `verification-report.md`)
- **ADR surface**: `docs/adr/3.x/` (new ADR + era index), lockfile
  `docs/development/3-2-page-inventory.yaml` (regenerated by the freshen script)
- **Amended ADR**: `docs/adr/3.x/2026-07-15-1-doctrine-offers-charter-activates-runtime-consumes.md`
  (status frontmatter only — C-003 carve-out)
- **Read-only inputs**: `contracts/` (artifact schemas), `data-model.md` (taxonomy + invariants),
  `research.md` (R1–R10 resolved unknowns), `quickstart.md` (verification runbook)
- No `src/`, `tests/`, or agent-directory changes in this mission (C-001).

## Work Package WP02: Occurrence Inventory — Mechanical Audit (Priority: P0)

**Goal**: Produce the evidence-based work list for the whole program — `inventory.md` with a raw
mechanical audit record, stable OC-## occurrence classes over the S1–S9 surface taxonomy,
classification-out rows (X1/X2/X3), the completeness arithmetic statement (0 unclassified hits), and
the out-of-repo deferral section.
**Independent Test**: The NFR-001 mechanical audit re-run finds 0 unclassified user-facing
occurrences; the completeness statement's arithmetic holds (SC-002).
**Prompt**: `/tasks/WP02-occurrence-inventory.md`
**Requirement Refs**: FR-006, FR-007, NFR-001, C-003, C-005

### Included Subtasks

T005 Run the mechanical audit at the base commit — `git ls-files` + case-insensitive per-file hit counts; record the raw output unmodified (evidence before conclusion)
T006 Classify every in-scope hit into OC-## occurrence classes (S1–S9 taxonomy) with stable IDs, path patterns, counts, and ≤3 representative examples each; apply the string-level scope rule (OC-I3)
T007 Build the classification-out table — X1 internal-identifier, X2 legacy-marked-historical (incl. `kitty-ops/` Op journals), X3 quoted-data — with counts and the rule applied per row
T008 Write `inventory.md` per `contracts/inventory-schema.md`: frontmatter, raw audit record, OC table, X table, completeness arithmetic statement, Section 5 out-of-repo surfaces

### Implementation Notes

- Audit **first**, classify second — the raw per-file record is committed evidence, not a
  reconstruction (ATDD-first analog from plan.md Charter Check).
- String-level scope rule (OC-I3): user-facing *strings* inside `src/` are in scope (S1/S7);
  identifiers anywhere are X1 — including the nuance that user-facing *artifacts* live inside
  `src/doctrine/` (skills at `src/doctrine/skills/`, 55 dirs incl. 7 `spk-doctrine-*`).
- Canonical-source split (research R7): `packs/built-in/` is the canonical YAML source;
  `src/doctrine/<kind>/` is Python code (identifiers out of scope per C-005).
- `assigned_mission` may be `TBD` in the inventory — it is finalized by WP04's assignment table;
  final state of the program has no TBDs.

### Parallel Opportunities

None — classification (T006/T007) consumes the raw audit record (T005); the artifact write (T008)
consumes both.

### Dependencies

- Depends on WP01 — classification rules cite the ADR's scope decisions, especially the
  operator-typed identifier split (IC-02 sequencing in plan.md).

### Risks & Mitigations

- **Completeness circularity (NFR-001)** → pinned by the mechanical procedure: every file with
  count > 0 appears in the raw record; no sampling, no hand-tallies; the arithmetic statement is the
  pass condition.
- **Misclassification of `src/` (path-level vs string-level)** → OC-I3 is applied per occurrence
  string; the prompt carries the S7 example (`src/charter/context_renderers/bootstrap_text.py`
  "Action Doctrine" heading) as the worked case.
- **Count drift from concurrent catfooding** → the inventory is a per-wave snapshot (INV-I1):
  `base_commit` is recorded in frontmatter; drift is re-baselined per wave, not silently absorbed.

## Work Package WP03: Ordering and Methodology Analysis (Priority: P1)

**Goal**: State *in what order and why* — `methodology.md` with the surface ordering and per-choice
rationale, the invariant that must hold at each stack level (I0–I6), the terminology-guard arming
design (file-level frozen baseline, shrink-only ratchet, self-mutation test), the per-surface
verification assignment for classes outside the guard's scan roots, and catfooding conflict
management (C1–C6).
**Independent Test**: A reviewer challenges each ordering choice and confirms every one has a stated
rationale tied to a concrete risk, plus the per-level invariant (US3-AS1); quickstart check 7 passes.
**Prompt**: `/tasks/WP03-ordering-methodology.md`
**Requirement Refs**: FR-008, C-004

### Included Subtasks

T009 Write the surface ordering with per-choice rationale (authority-first; atomic authority flip) and state invariants I0–I6 for each stack level
T010 Write the guard-arming design — file-level frozen exemption baseline (shrink-only ratchet + self-mutation test per Standing Order #5), the stated blind spot, and string-fragment construction for alias tests
T011 Write the per-surface verification assignment — exactly one named mechanism for each class outside the guard's scan roots (S5/S6/S8/S9, plus the out-of-root portions of mixed-root classes S4 and S7 — `data-model.md` §1) per C-004
T012 Write catfooding conflict management (C1–C6) plus alias introduction/removal verification (3.x hidden + warning, per-subcommand tests; 4.0 removal by audit) and per-wave re-baselining (INV-I1)

### Implementation Notes

- The load-bearing design is the **atomic authority flip** (research R8/C1): glossary rewrite +
  charter-bundle update + guard arming land in one mission/PR (M1, guard-arming WP last) so no
  conflict window exists where the old word is forbidden and the replacement is not yet canonical
  (INV-I2).
- Guard state at base (research R2, verified live): `_FORBIDDEN_TERMS` = ceremony + status-writing
  only; `_SCAN_ROOTS` = `src/tests/docs`; exclusions are path-fragment based with **no per-file
  exemption mechanism for active surfaces** — arming is new machinery, not a config tweak.
- Invariants I0–I6 and the C1–C6 conflict set are already fixed in `data-model.md` §5 and
  `research.md` R8 — this WP writes them up as the methodology's core content with per-choice
  rationale, not re-decides them.

### Parallel Opportunities

None — the four sections of `methodology.md` interlock (ordering cites invariants; guard design
cites the ordering's atomic-flip rationale).

### Dependencies

- Depends on WP02 — ordering rationale cites inventory evidence (counts, class structure).
- Also consumes WP01's ADR (guard-arming intent is content-contract item 9).

### Risks & Mitigations

- **Guard design fails Standing Order #5 (non-vacuous gate)** → the prompt requires the concrete
  floor + shrink-only ratchet + self-mutation test as explicit sections, with the known blind spot
  (count growth inside baseline files) stated and assigned to per-wave re-baselining.
- **Out-of-root classes left unverified (C-004)** → T011 is a table: one row per out-of-root
  class (S5/S6/S8/S9 + S4's and S7's out-of-root portions), exactly one named mechanism each;
  quickstart check 7 verifies the table.
- **Re-deciding operator-approved content** → shape and invariants are fixed by the plan +
  research; this WP's job is rationale + mechanism detail, not new decisions.
