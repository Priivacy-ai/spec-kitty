# Решения

Владение только явно через штатный classifier. Поддержка первого патча
ограничена single_branch. Политика primary остаётся независимой от рабочего
корня. Новый алгоритм размещения не создаётся.

Для приёмки тот же effective_root проходит через библиотеку проверок и матрицу.
В переносе статусов используется проверенный OwnedMission: оба точных каталога
повторно проверяются до первой записи, затем передаются через seed/verify/flip.
Общий canonicalizer, event store и reducer не меняются. Это закрывает повторное
перенаправление в primary без второго writer и без ослабления ownership.
Неуспешный stamp в явном режиме возвращает ошибку; прежний best-effort режим
без нового параметра сохранён. Пустой index обязателен перед пишущим режимом.

Проект дополнения `move-task`: тот же OwnedMission проходит через прямые
consumers, а база сравнения остаётся отдельно от target записи. Она нужна только
для штатных проверок реализации/актуальности ревью, а не для назначения или
мотивированного возврата. После read-only аудита выбран один последовательный
пакет без нового resolver. Формальная приёмка вынесена из подзадач реализации,
чтобы избежать циклического требования её завершённости перед ревью.
Это согласуемый план, не реализация и не изменение канонического статуса.
