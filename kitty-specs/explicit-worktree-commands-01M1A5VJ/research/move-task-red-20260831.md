Дополнение локального ремонта одобрено командой оператора «дальше».

## Наблюдаемый результат

`tests/integration/test_owned_checkout_move_task.py` создаёт настоящий Git-репозиторий
и две связанные внешние рабочие копии. Документы существуют только в выбранной.
Штатный `finalize-tasks --owned-checkout` сохраняет канонический `planned`,
а `check-prerequisites --owned-checkout` читает точный каталог успешно.

Старый entrypoint `tasks.app move-task WP01 --to doing --agent codex --mission
owned-01M1A900 --json` возвращает код 2 и `mission_not_found`. Тест падает именно
на ожидаемом успешном коде, не на parser, импорте или подготовке fixture.
Результат: **1 passed, 1 failed**. Снимки HEAD, index, status и файлов подтверждают
неизменность primary, соседней и выбранной копии при отказе.

Этот commit сохраняет исходное воспроизведение, не готовое исправление.
При реализации явного режима успешный вызов получит `--owned-checkout`,
а прежний вызов без флага останется отрицательным compatibility control.
Менять неявное разрешение корня ради зелёного теста запрещено.

## Запуск

`python -B -m pytest tests/integration/test_owned_checkout_move_task.py
--confcutdir=tests/integration -p no:cacheprovider -q --basetemp <temporary-path>`

Перед импортом заданы временные HOME, USERPROFILE, SPEC_KITTY_HOME, APPDATA,
LOCALAPPDATA, TEMP и TMP, отключена SaaS-синхронизация. Корневой CLI не вызывается.
Штатные проверки статуса/путей не подменены. Fixture использует игнорирование
`.kittify/sync-state.json` из реального `.gitignore`; содержимое файла при этом
входит в snapshot и не скрывается от проверки изоляции.

Ruff: успешно. Карта кода расширена до существующей цепочки move-task;
реализация нового режима в ней пока не заявлена.

Независимое чтение: RED-checkpoint допустим, блокеров нет; это не verdict
готового исправления. По замечанию reviewer тест теперь проверяет точные exit 2
и JSON mission_not_found до ожидаемого падения. Snapshot проверяет staged diff,
а не сырые байты index или все общие refs; assertions успешного перехода пока
не достигнуты и не объявляются пройденными.

## Ограничения запуска

Первый старт pytest прерван: сохранённый helper прошлого хода оказался недоступен,
PowerShell продолжил команду без изоляции и создал тестовые данные в `C:/p`.
Этот запуск не является доказательством. Следующие запуски используют явный
setup и `$ErrorActionPreference = 'Stop'`; ошибки fixture отдельно устранены
до содержательного воспроизведения. Корневой CLI и установка не запускались;
неизменность всей пользовательской среды первым запуском не доказана.
Попытка удалить только идентифицированный тестовый каталог `C:/p` отвергнута
политикой инструментов до запуска. Каталог сохранён; обход отказа не выполнялся.
