# Результаты локальной проверки

## Реализация

Три команды поддерживают явный `--owned-checkout` для `single_branch`.
Общая проверка выполняется до чтения документов и записи. Canonical primary
остаётся источником политики, проверенный checkout определяет локальное чтение,
статусы, матрицы, commit и `sync-state.json`. Без флага прежний маршрут сохранён.
Полная пачка путей проверяется до staging; при существующем index запись
отклоняется без stash. Изменений схемы метаданных не требуется.

В разрешённом потоке потребовалась передача корня также через writers матриц
и локальную запись commit-notification. Это уточнение реализации, без расширения
команд или поддерживаемых topology. Карта и границы разрешённых файлов обновлены.

## Доказательства

- Исходный дефект поиска документов воспроизведён до реализации на базовом CLI.
- Отдельный тест повреждённого `.git` на Windows падал на fixture `PermissionError`.
  `r+` с `truncate()` сохранил реальный повреждённый pointer и исходные assertions.
  Дефект зарегистрирован отдельно: https://github.com/Priivacy-ai/spec-kitty/issues/3822 .
- `tests/integration/test_explicit_checkout_commands.py`: **51 passed**.
  Проверены три entrypoint, повторные запуски, одинаковый slug, primary/sibling cwd,
  вложенный/чужой/повреждённый checkout, ссылки наружу, protected/detached/mismatched
  ветки, смешанная пачка путей, index, статус и обе матрицы. Сравниваются HEAD,
  staged diff, tracked/untracked содержимое трёх checkout.
- Связанный первый набор: **114 passed**, два отказа из-за лишнего `None` аргумента
  в подменённом resolver. Прежний вызов восстановлен, этот файл повторно прошёл
  в следующем наборе.
- Размещение, разделение commit, runtime и sync wiring: **317 passed, 11 skipped**.
  Пропуски не считаются подтверждённым поведением.
- Классификатор владения и bootstrap входят в первый набор; Windows fixture зелёная.
- Ruff: **passed** для всех изменённых Python-файлов и нового helper.
- Mypy: **17 ошибок** существующих `Any`/import-skip контрактов. Сравнение с архивом
  исходного commit `603e7b250` даёт тот же набор 17 сообщений в тех же функциях;
  новых ошибок нет. Общую проверку типов зелёной не объявляем.
- Значимая мутация expected пути `owned` на `primary` в изолированном pytest
  процессе дала **1 failed**, именно `AssertionError` сравнения пути, без ошибки
  parser/fixture. Исходный acceptance-тест не изменялся.
- Независимый reviewer: **APPROVE**, повторная проверка **19 passed** и чистый diff.

## Применение к исходной задаче

Проверка документов `cli-opportunity` вернула `valid=true`, без предупреждений,
и правильный внешний worktree. Предварительная финализация больше не теряет корень:
она сообщает отдельную ошибку документа `tasks.md`, в котором не распознана секция
WP01. Исходные документы не изменялись, обычная финализация не запускалась.

## Ограничения завершения

Hosted sync и общий запуск CLI с реальным глобальным bootstrap не входят в
изолированное доказательство. Один проверочный root-запуск вызвал глобальный
bootstrap вопреки границе локальной доставки; операционный инцидент зафиксирован
в родительской задаче. Последующие root-проверки выполнялись с отдельными временными
HOME, USERPROFILE и SPEC_KITTY_HOME. Восстановление глобальных файлов не выполнялось.
`accept --diagnose --json` через отдельный Typer entrypoint, без глобального
startup, вернул `mission_not_found`: эта четвёртая команда не поддерживает
новый параметр и не входит в согласованный патч. Формальная приёмка не объявлена,
публикация и установка навыка не выполнялись.
