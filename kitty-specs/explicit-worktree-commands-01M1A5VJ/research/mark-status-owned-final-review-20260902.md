# Финальная проверка owned mark-status

Дата: 2026-09-02

## Смысловые мутации

1. Удаление `effective_root` из `TASKS_INDEX` чтения заставило real-Git тест с
   теневой mission прочитать primary и содержательно упасть: `T001 not_found`.
2. Принудительный `state_applied=false` заставил тест частичного multi-WP сбоя
   упасть на точном observable поле.

После каждой мутации код восстановлен точечным патчем; `git diff --exit-code`
подтвердил отсутствие остаточных изменений.

## Независимое ревью

Первое read-only ревью точного diff выявило P2: общий scan новых filesystem
events мог приписать текущей команде событие конкурентного writer между двумя
WP-транзакциями.

Исправление разделило два случая:

- обычная ошибка сообщает только `event_ids/applied_wps`, которые уже вернули
  транзакции текущей команды;
- recovery-after-commit берёт точный `commit_sha` из цепочки исключений и
  извлекает только события этого commit относительно parent.

Два новых теста закрепили конкурентную запись и точный recovery commit.
Повторное независимое ревью вернуло `APPROVE` без P1/P2.

Residual risk: если локальные Git objects или JSONL повреждены и точный commit
нельзя прочитать, envelope консервативно не приписывает сомнительные события.
Durable Git/status state при этом остаётся источником истины.
