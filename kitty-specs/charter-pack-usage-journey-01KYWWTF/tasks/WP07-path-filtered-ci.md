## Objective

Give PRs that touch the doctrine/charter layer fast, isolated CI feedback, and spare unrelated PRs that
cost/noise. Add a **path-filtered GitHub Actions workflow** scoped to `src/doctrine/**`, `src/charter/**`,
**and `src/specify_cli/invocation/**`** that runs the doctrine/charter test surface. Closes **#3102**.

**Why `src/specify_cli/invocation/**` is in the filter (squad MAJOR, alphonso M1):** the #3104 P1 centerpiece
`is_charter_empty` and its dispatch-net tests live there — a bare `src/charter/**`+`src/doctrine/**` filter
would leave the P1 fix ungated (false-green). Include it, or explicitly document that those tests ride main CI
only. Prefer including it.

## Guidance

### T060 — The path-filtered workflow

Author `.github/workflows/doctrine-charter-tests.yml` triggered on PRs with `paths:` covering
`src/doctrine/**`, `src/charter/**`, `src/specify_cli/invocation/**` (and likely the mirrored `tests/`
subtrees). It should run the fast doctrine/charter signal: DRG freshness/sharding, charter-context
resolution, and the layer-relevant architectural/adversarial gates — **not** a duplicate of the full suite the
main CI already runs. Mirror the repo's existing workflow conventions (setup, `uv`, caching, headless env).

### T061 — Skip-with-green + no double-charge

Ensure a PR that changes **none** of the filtered paths **skips-with-green** (a required check satisfied when
skipped), never skip-with-fail — consistent with the repo's existing path-filter un-skip semantics. Verify the
job does not re-run gates the main CI already charges. Document (in the workflow header or the PR) exactly
which gates this workflow owns vs the main CI. If the repo uses a required-status-check convention (a gate
job that always reports), follow it so branch protection stays satisfiable.
