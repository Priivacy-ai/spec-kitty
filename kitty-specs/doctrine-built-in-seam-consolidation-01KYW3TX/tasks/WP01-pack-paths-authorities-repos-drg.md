## Objective

Create the **two** on-disk location authorities the whole mission hangs on — `built_in_dir(kind)`
(per-kind) and `built_in_root()` (root) — in `src/doctrine/pack_paths.py`, then route the first tier
of callers through them: the **9 doctrine-repository defaults** and the **2 DRG root callers**. This
is the foundation WP (FR-001/FR-001b/FR-005 plus the FR-002 repo+DRG slice); it is purely additive and
behaviour-preserving, so it can land with zero dependencies. Every later WP (WP02–WP05, WP07) consumes
these authorities; WP04's anti-regression ratchet allow-lists **only** these two functions.

Read first (authoritative, do not re-derive): `../contracts/built-in-location-authority.md` (C1.1–C1.6),
`../spec.md` (FR-001, FR-001b, FR-002, FR-004, FR-005; Edge Cases on the 3-kind carve-out),
`../plan.md` IC-01. Ground in `src/doctrine/pack_paths.py` (`resolve_pack_root` at :61, `_resolve_built_in`
at :90, current `__all__` at :45) and `src/doctrine/artifact_kinds.py` (`ArtifactKind.plural` at :113;
`_NON_AUGMENTATION_ELIGIBLE_KINDS` at :201 = `{TEMPLATE, ASSET, ANTI_PATTERN}` — **the WRONG set** for
this carve-out: it carries `asset` (which HAS a content dir) and omits `mission_step_contract`. Do NOT
reuse it; T001 adds the correct SSOT attribute here).

**Do NOT** change the `Repository(built_in_dir=…)` *leaf* constructor parameter (a different,
already-flat param that stays — occurrence_map exceptions in `tests/doctrine/test_service*.py`). This
WP only changes each repository's *default* computation. **Do NOT** touch `DoctrineService.built_in_root`
here — that param drop is WP04.

## Subtasks

### T001 — Add the content-dir SSOT attribute in `artifact_kinds.py`, then the two authorities + derived-complement raise
This is the adjudicated carve-out mechanism: **introduce ONE derivation attribute in `artifact_kinds.py`**
so the complement is computed, never hand-listed (FR-005/NFR-005 "derived, not hand-listed").
- In `src/doctrine/artifact_kinds.py`: add a single source of truth for "which kinds ship a
  `packs/built-in/<plural>/` content dir" — either a per-member property `has_built_in_content_dir: bool`
  or a module-level `_BUILT_IN_CONTENT_KINDS: frozenset[ArtifactKind]` naming exactly the **9** content-dir
  kinds (`agent_profiles, assets, directives, glossary_packs, paradigms, procedures, styleguides, tactics,
  toolguides`). Do NOT reuse `_NON_AUGMENTATION_ELIGIBLE_KINDS` (wrong set — see Objective). Import stays
  leaf: `artifact_kinds` imports only `enum` today; adding a frozenset of its own members introduces no
  cycle.
- In `src/doctrine/pack_paths.py`, add `built_in_root() -> Path` returning `resolve_pack_root("built-in")`
  (FR-001b) — the single callable root-needing readers use instead of scattering bare
  `resolve_pack_root("built-in")`.
- Add `built_in_dir(kind: ArtifactKind) -> Path` returning `resolve_pack_root("built-in") / kind.plural`
  with the plural read from the canonical `ArtifactKind` (FR-001).
- Before composing the join, refuse the **derived complement** — every kind for which the new attribute is
  false, i.e. `{mission_step_contract, template, anti_pattern}` — with a named, explanatory error
  (FR-005 / C1.4). Because the complement is `ArtifactKind` members MINUS the attribute set, a kind
  gaining or losing a content dir edits exactly ONE SSOT place in `artifact_kinds.py`; `built_in_dir`
  contains no literal set. Message names the kind and says it is package-resource/graph-only (point at
  #3091 for step-contract/template relocation).
- Extend `pack_paths.__all__` with `built_in_root` and `built_in_dir`. Missing/unlocatable root already
  raises `PackRootNotFound` inside `resolve_pack_root` (FR-004 / C1.3) — do not add an empty-set fallback.

### T002 — Route the 9 repository defaults through `built_in_dir(kind)`
Each of the 9 `src/doctrine/<kind>/repository.py` computes its default built-in directory in
`_default_built_in_dir()` (or equivalent). Replace the hand-written
`resolve_pack_root("built-in") / "<plural>"` (or any residual nested `src/doctrine/<kind>/built-in`
shape) with a call to `built_in_dir(<this kind>)`. Kinds: `agent_profiles`, `assets`, `directives`,
`glossary_packs`, `paradigms`, `procedures`, `styleguides`, `tactics`, `toolguides`. Pass the kind's
canonical `ArtifactKind` member (not a string). Behaviour is unchanged — repos already self-resolve
flat; this only relocates the *join* into the authority. Confirm no repository is left deriving its own
path.

### T003 — Route the 2 DRG root callers through `built_in_root()`
Repoint the two bare root calls to the seam (FR-001b / C1.6):
- `src/doctrine/drg/loader.py:135` — `return resolve_pack_root("built-in")` → `return built_in_root()`.
- `src/doctrine/drg/migration/extractor.py:113` — `return resolve_pack_root("built-in")` → `return built_in_root()`.
Import `built_in_root` from `doctrine.pack_paths`. These are root-needing (no kind dir), so
`built_in_dir` is the wrong tool — `built_in_root()` is exactly the FR-001b affordance. (The remaining
root callers — `bootstrap_text.py:271`, `doctrine.py:210` — are WP02/WP03; do not touch them here.)

## Risks
- **Import cycle**: `pack_paths` importing `artifact_kinds` — verified leaf today (`artifact_kinds`
  imports only `enum`); re-confirm after the edit (a cycle would break the whole doctrine import layer).
- **Wrong SSOT set**: reusing `_NON_AUGMENTATION_ELIGIBLE_KINDS` (has `asset`, omits
  `mission_step_contract`) would make `built_in_dir(asset)` raise wrongly and `built_in_dir(step_contract)`
  resolve to a non-existent dir. Add a NEW attribute for the 9 content-dir kinds.
- **Hand-listed carve-out regression**: if the complement is typed as a literal `{...}` set in
  `pack_paths.py` it silently drifts (NFR-005). Compute it from the `artifact_kinds` attribute; WP04's
  `#3091`-marked gate will additionally pin it.
- **Wrong param touched**: the leaf `Repository(built_in_dir=…)` param is NOT this WP — only the repo
  *default* computation.
