# Operator ruling — WP02 HALT, mission `spdd-reasons-activation-split-brain-01M1K6VN`

Date: 2026-09-03. Issued by the operator (Human-in-Charge) via the mission orchestrator.

WP02's implementation is spec-faithful: its six red-first tests are green, all gates pass, and its
`None -> catalog default` semantics for `project_directives` are exactly what FR-006, FR-008 and
Decision Record 2 mandate. It nonetheless breaks two binding regression tests owned by other
missions:

- `tests/charter/test_directive_003_implement_to_review.py::test_implement_lacks_003_but_review_still_delivers_it`
  (FR-005) — DIRECTIVE_003 leaks onto `implement`'s delivered set, which FR-005 forbids.
- `tests/charter/test_context.py::test_action_doctrine_keys_off_meta_json_not_template_set`
  (the #883 cross-mission-type leak-prevention regression).

**This ruling REPLACES the acceptance bar for WP02.**

## The actual defect

`_classify_artifact_urns` in `delivery_table.py` uses `project_directives` for **two semantically
different jobs**:

1. the exclusion-guard **allowlist** — what the project is permitted to deliver;
2. the **seed set** for a `resolve_transitive_refs` closure walk over `requires`/`suggests` edges,
   whose result is unioned into the delivered set **with no scope-reachability check**
   (`walk_edges` returns "all visited node URNs including start nodes").

`None -> all built-ins` is the correct semantics for an allowlist: an unconfigured project permits
everything. It is the wrong semantics for a seed: a walk should start from what is in scope for the
action being resolved, not from everything permitted.

Conflating an allowlist with a seed set is the defect. It is **pre-existing and latent** — before
this mission `project_directives` was always empty, so job (2) never fired. WP02 did not introduce
it; WP02 stopped it being dormant.

## Ruling — scope-gate the closure walk

**Separate the two uses, and union only closure results actually reachable within the resolving
action's own scope edges.** `delivery_table.py` is in WP02's `owned_files`, so this is the
mission's to fix.

This satisfies all three constraints simultaneously, which is why it is preferred over either
alternative:

- DIRECTIVE_003 is not reachable within `implement`'s scope, so it stops leaking — **FR-005 passes**.
- The cross-mission-type walk is bounded, so **#883 stays closed**.
- The closure still widens from the catalog default, bounded by scope — **WP02's FR-008 / T007
  case 4 remains true as written**, with no spec walk-back.

**Acceptance signal**: both named tests must pass **UNMODIFIED**. Verify by `diff` against their
pre-mission content, not by "they pass" — a sibling mission this week used byte-identity as the
signal precisely because a passing test that was quietly edited proves nothing.

The fix requires its own red-first fixture: a test that fails against the scope-ungated walk and
passes after, proven by reverting the gate and observing the failure, then restoring.

## Alternatives considered and rejected

1. **Narrow the catalog default for closure-seeding only** — let `None -> all built-ins` feed the
   exclusion-guard allowlist but not the seed. Rejected on two grounds. It contradicts T007 case 4
   and FR-008 as explicitly tested, making it a spec walk-back rather than a code fix. And it leaves
   the unscoped closure walk intact and merely un-triggered — the same landmine, dormant again, for
   the next mission to detonate. This mission exists because a latent silent-collapse defect was
   left dormant; re-arming one to close it would be self-defeating.
2. **Update FR-005 and #883's tests as stale**, on the grounds that this mission legitimately
   redefines "activated" for an unconfigured project. Rejected. #883 encodes a cross-mission-type
   leak that **already shipped once and was fixed**. Rewriting a regression test to accommodate a
   new change is precisely how that defect returns, and "the other mission's assumptions are stale"
   is the most comfortable available answer, which is reason for suspicion rather than confidence.

## Scope note

The defect is pre-existing, so folding its fix into this mission widens WP02. That is deliberate.
A change that breaks two binding contracts cannot be shipped with the breakage recorded as someone
else's problem, and the file is already owned by this work package. Fold it in; do not open a
follow-up issue.

## How WP02 closes

Implement the scope gate with its red-first fixture, re-run the full scoped path set, confirm both
named tests pass unmodified, then a fresh independent reviewer — never WP02's implementer. All
green -> WP02 proceeds to `for_review` through `mark-status` per subtask, never `--force`
(ledger SK-157).
