# Operator ruling 2 — WP02 second HALT, mission `spdd-reasons-activation-split-brain-01M1K6VN`

Date: 2026-09-03. Issued by the operator (Human-in-Charge) via the mission orchestrator.
Supplements `wp02.ruling.md`, which stands unchanged.

The scope-gate fix ruled in `wp02.ruling.md` worked and is not in question:
`test_implement_lacks_003_but_review_still_delivers_it` passes with its content **byte-identical**
to pre-mission, and the gate's own red-first fixture is genuinely proven (DIRECTIVE_010 leaked into
`implement` before the gate, absent after).

A second, independent collision remains, on the **allowlist** side that ruling 1 declared correct
and left untouched.

## The tension

`test_action_doctrine_keys_off_meta_json_not_template_set` (the #883 regression) patches
`charter.activation._drg_helpers.load_validated_graph` with a mock graph containing a fictional
`DIRECTIVE_100` that exists only in that mock. **It does not mock where the catalog default comes
from.** The test is therefore half-hermetic: the graph is synthetic, the "all built-ins" set is
real.

That was invisible while `project_directives` was always empty. Under this mission's ruled
semantics an unconfigured project's `activated_directives=None` resolves to the real catalog
(~34 ids), `DIRECTIVE_100` is not among them, the allowlist excludes it, and the test's first
assertion fails.

The obvious fix — widening the allowlist to admit ids outside the real catalog — is **rejected**,
and the implementer was right to refuse it unprompted. It reintroduces silent widening, the exact
defect class this mission exists to close, and it breaks an already-green, directly-relevant test:
`test_action_bundle_delivery.py::test_classify_skips_unresolvable_urn_and_out_of_scope_directive`.

## Ruling — resolve the default from the active DRG

**`None -> all built-ins` must resolve from the graph actually in play, not from a hardcoded real
catalog.**

In production the active graph *is* the real catalog, so behaviour is unchanged. Under an injected
or mocked graph, "all built-ins" means that graph's directives — so `DIRECTIVE_100` is admitted and
**#883's test passes completely unmodified: assertions and fixture both.**

This is also the more correct semantics on its own merits, independent of the test. A default over
"all built-ins" should mean the built-ins of the graph being resolved against. Binding it to a
global real catalog is what made a mocked graph and a real allowlist disagree in the first place —
the same conflation-of-two-sources shape as ruling 1's allowlist-versus-seed defect.

**Acceptance signals — all three, verified by `diff` against pre-mission content, not by
"they pass":**

1. `test_action_doctrine_keys_off_meta_json_not_template_set` — passes, **byte-identical**.
2. `test_implement_lacks_003_but_review_still_delivers_it` — still passes, **byte-identical**
   (do not regress ruling 1).
3. `test_action_bundle_delivery.py::test_classify_skips_unresolvable_urn_and_out_of_scope_directive`
   — **still passes**. It uses a non-empty explicit `project_directives`, so default resolution
   should never fire for it. **Verify that, do not assume it.** If it does break, that falsifies
   this ruling and is an immediate HALT back to the operator.

Plus a red-first fixture for the resolution change itself, proven by reverting to catalog-sourced
resolution and observing the failure, then restoring.

## Alternatives considered and rejected

1. **Set explicit `activated_directives` in #883's fixture** so it no longer depends on the default.
   Assertions would stay byte-identical and only setup would change; defensible, since the test is
   named for `meta.json` keying and its reliance on the default is incidental. Rejected because it
   leaves the half-mocked pattern in place for the next test to trip over, and fixes one test rather
   than the mismatch.
2. **Mock the catalog-default source alongside the graph**, making the test consistently hermetic.
   Same objection: it repairs this fixture and leaves the underlying source-conflation intact.
3. **Widen the allowlist to admit non-catalog ids.** Rejected on evidence — falsified by an
   already-green sibling test, and it re-arms the silent-widening class.

## Note on consistency with ruling 1

Ruling 1 rejected "treat FR-005 and #883's tests as stale". This ruling does not reverse that. It
requires #883's test to pass **completely unmodified** — no assertion changed, no fixture changed.
The change lands in production semantics, where the defect actually is. Options 1 and 2 above,
which would have edited the test's setup, are the ones being declined.
