## Why the glob lines live here and not in IC-03

The plan lists the two `egress.py` glob lines as IC-03 tasks 2 and 3. They are **moved into this WP**
so that **one work package owns `.github/workflows/ci-quality.yml`** (lane write-scope: a WP that must
write another lane's file is a hard stop at implement time), and so that the review question *"are
there **two**?"* is asked in one place rather than split across two packages.

**Consequence, stated so it is not read as a defect**: T011/T012 add globs for
`src/specify_cli/egress.py`, a file **WP03 has not created yet**. A dorny filter glob that matches
nothing is inert — it changes no job selection until the file exists — and `_gate_coverage`'s
`_src_dir_of_glob` returns `None` for any `src/specify_cli/<file>.py` glob, so it maps no src
directory and joins no worklist. **If a gate does object to a glob for a not-yet-existing path, stop
and record it**: the fallback is to move T011/T012 into WP03 (which then owns `ci-quality.yml`, and
WP02 still lands first). Do not improvise a third arrangement.
