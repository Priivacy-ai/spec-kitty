# Tracer: Design Decisions

| Date | Decision | Why |
|------|----------|-----|
| 2026-08-14 | FR-001 is a NEW per-token predicate, not a promotion of `find_undeclared_requirement_citations` | That function's zero-declared trigger (`not _declared_ids(section)`) never fires on a section that declares some requirements and bare-prose-writes others — verified directly, it returns `[]` against the issue's own repro. Promoting it would ship a gate that never blocks on the case this mission exists to catch. |
| 2026-08-14 | The declared-id set the new predicate checks against is document-scoped, not section-scoped (C-006) | Measured directly: document-scoped flags 9/368 (2.45%) of the corpus; section-scoped flags 139/368 (37.77%) — a 15x difference from one word of design intent. A token declared elsewhere in the document is already counted as a requirement, so a section merely citing it is not a lost requirement; the narrower reading is the correct one, and is now a binding constraint rather than an implementer's silent guess. |
| 2026-08-14 | The invented <=2% false-positive/ambiguous-block ceiling, the three-bin classification scheme, and the post-plan review-squad exception clause are deleted, not narrowed | They existed to gate an unmeasured risk. The risk is now measured (2.45%, zero true positives, all in the class Story 2 AC3 already pins as non-blocking) and is already above the invented ceiling — keeping the ceiling apparatus would make the spec actively wrong, not merely redundant machinery. |
| 2026-08-14 | CI protection is a frozen, shrink-only corpus fixture under `tests/`, not a live re-run over `kitty-specs/` | A live re-run would let an unrelated future mission's spec.md determine this gate's colour, and would ship already-red at the measured 2.45% — both horns of squad finding SPEC-FRESH2-002. A frozen, deliberately-re-snapshotted fixture (charter Standing Order 5, `frozen-baseline-shrink-only-ratchet`) is a concrete floor that is non-vacuous (a broadened detector trips it) without either defect. |
| 2026-08-14 | The false-negative sample (C-XXX-under-"Constraints"-heading case) is retained, not deleted, despite deleting the ceiling apparatus | It is orthogonal to the ceiling/three-bin scheme the remedy targeted — it measures under-firing, a different defect class than the over-firing the deleted apparatus gated, and C-008/Edge Cases (left untouched per the arbiter's ruling) depend on it being present. |
| 2026-08-14 (plan) | C-008 resolved as option (b): `_is_requirement_heading` stays byte-identical; `C-XXX` bare-prose under `### Constraints` stays out of blocking scope this mission | Broadening to also match "constraint" would pull ~325/368 (88.32%) of the corpus into blocking scope with zero corresponding FP re-measurement, directly conflicting with the instruction not to relitigate the already-measured, pinned 9/368 (2.45%) figure. The spec's own Key Entities text explicitly sanctions "document as an accepted scope narrowing" as a valid outcome. |
| 2026-08-14 (plan) | The new bare-prose fact is a sibling `BareProseRequirementFacts` dataclass in `runtime_bridge_cores.py`, not an extension of `RequirementMappingFacts` | `RequirementMappingFacts` is WP-shaped (`wp_ids`/`wp_requirement_refs`) and its residual gather (`_check_requirement_mapping_ready`) early-returns when `tasks_dir` is absent — exactly the dependency FR-002 requires the new signal to be independent of. Reusing it would force dummy WP fields or duplicate the early-return logic; a sibling object with its own independent residual gather (spec.md only, no tasks_dir dependency) is the clean C-007-compliant shape. |
| 2026-08-14 (plan) | The new signal is wired into all four plausible guard functions (`_evaluate_tasks_packages_guard`, `_evaluate_tasks_finalize_guard`, `_evaluate_composed_tasks_packages_guard`, `_evaluate_composed_tasks_terminal_guard`), not only the three FR-003's audit proved live for the built-in mission type | The CLI-native pair is proven non-primary, not proven dead — a custom mission type without a matching `action_sequence`/contract binding still falls back to it. NFR-002's silent-success prohibition argues for closing `_evaluate_tasks_finalize_guard`'s pre-existing asymmetry (it already reads `occurrence_gate_failures` but never `requirement_mapping_failures`) rather than leaving one guard in the family structurally blind by construction. |
| 2026-08-14 (plan) | PR base is `op/3394-requirement-citation-scope`, not `main` | Basing on `main` would show #3395's ~863-line unreviewed parser rewrite as part of this mission's own PR diff, making it unreviewable in isolation. GitHub auto-retargets to `main` once #3395 merges — no manual step needed for that transition. This is the operator's already-recorded decision; the plan phase only had to justify, not choose. |
| 2026-08-14 (plan-fix, PLAN-GOV-002) | C-008's disposition (b) is kept, but on a measured basis: a real broadened-predicate FP scan was run (not skipped) | A read-only corpus scan against `kitty-specs/*/spec.md` (368 specs) with `_is_requirement_heading` broadened to also match `"constraint"` found only 5/368 (1.36%) newly-flagged specs, 8 candidate tokens (raw per-occurrence count, no dedup step — matching the Architecture section's own algorithm), zero true positives on manual review — plus a genuine broadening-specific over-match risk (a plain `"constraint"` substring also matches non-canonical "Carried constraints —..." narrative headings, not only the canonical `### Constraints` table). Disposition (b) is kept because shipping a *production-quality* broadened predicate still needs the same double-independent verification rigor FR-005's settled 9/368 figure already required, plus a smarter (non-substring) heading-match design — a cost this plan phase judged disproportionate, not because the FP data was unavailable. |
| 2026-08-14 (plan-fix, PLAN-ARCH-001) | The four guards read the new `bare_prose_requirement_failures` status_facts key via `.get(key, ())`, not a bare `[]` subscript | `tests/runtime/test_bridge_cores.py`'s shared `_snapshot()` helper does not populate the new key, so a bare subscript would raise `KeyError` in every existing `evaluate_guards` test the instant the guard is wired. `.get()` degrades gracefully for any caller/fixture that predates this mission's wiring, without requiring a coordinated fixture-update commit landed in lockstep; `_snapshot()` should still be updated for fixture accuracy as a follow-up hygiene item, not a blocking dependency. |
| 2026-08-14 (plan-fix, PLAN-GOV-001) | `_validate_requirement_mapping` (`mission_finalize.py:621-677`, complexity 16 > charter's 15 ceiling, confirmed with `radon cc`) is extracted into a classification helper + a report-formatting helper as the campsite-clean FIRST commit, before IC-03's functional addition | IC-03 schedules a new branch into this exact function; landing it unremediated would push an already-over-ceiling function further over. The split isolates the per-WP classification loop from the JSON/console report-formatting branch — behaviour-preserving, verified sub-ceiling by `radon cc` before IC-03's commit is authored. |
| 2026-08-14 (tasks) | WP02 (the campsite-clean split of `_validate_requirement_mapping`) does not carry a literal charter-C-011 failing-first ATDD test; its regression guard is instead "every pre-existing test on the function stays green, unmodified" | C-011's failing-first clause exists to pin *new user-observable behaviour*; a behaviour-preserving extraction introduces none. Plan.md's IC map does not state an ATDD-applicability rule for this concern, so this is a tasks-authoring judgment call, recorded here rather than left implicit — every other WP that adds new behaviour (WP03, WP05, WP06) does carry the literal RED-before-GREEN commit pair, verified against `ab15225ea`. |
| 2026-08-14 (tasks) | The mission brief's chokepoint rule ("touching runtime-state schema / a shared CI gate serializes the mission whether or not you want it parallel") is read as full-mission serialization at that point — WP05 and WP08 run with nothing else scheduled concurrently, not merely "not paired with another chokepoint-touching WP" | The brief's literal wording ("serializes the mission") supports either the conservative (nothing else runs) or a narrower (no two chokepoint-touching WPs run together) reading; WP06/WP07 are otherwise file-disjoint from WP05 and could, under the narrower reading, have run concurrently with it. The conservative reading was chosen because it is the one that cannot silently violate the instruction if the narrower reading was intended, at the cost of some schedule concurrency; recorded here as a judgment call a reviewer may want to revisit rather than an unstated default. |
