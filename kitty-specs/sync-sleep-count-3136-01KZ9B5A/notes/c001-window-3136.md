### The "same session" ambiguity — named, not papered over

`NFR-005` (`spec.md:472`) requires that *"The baseline must be captured in the same session as the
comparison."* Taken literally that is **unachievable in this mission's own process model**, and the
conflict is recorded here rather than quietly ignored:

- The comparison arm cannot exist until WP02 has landed the seam and the 24 retargets.
- WP01 must reach `approved` before WP02 can be claimed (`plan.md:1257` — `WP02 … deps: WP01`).
- Therefore the two arms are necessarily taken by **two different agents in two different sessions**.

**Operationalisation (binding for this mission):** *"same session"* is read as **"the same held
`C-001` window, the same interpreter, `python -V` printed on both arms"**. That is what the criterion
`SC-014` actually checks (`spec.md:899-905`): *"Both arms, same command, same interpreter … and
`./.venv/bin/python -V` for each arm (**must be identical**, and must be 3.12.x). A delta measured
across two interpreters is not a measurement."* SC-014 says nothing about a single OS session; it
constrains the **interpreter**.

This window spanning the whole critical path (`WP01 → WP02 → WP05 → WP07`) is exactly what makes that
reading legitimate: no `tests/cli` run and no foreign `tests/sync` run can interleave between the two
arms, because the window is held continuously from `2026-08-06T22:46:46Z` until WP07's T043 releases
it. **If the window is ever released and re-acquired between the two arms, the NFR-005 delta is void
and the base arm must be retaken.**
