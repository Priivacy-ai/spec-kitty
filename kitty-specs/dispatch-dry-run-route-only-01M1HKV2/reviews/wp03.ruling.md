# Operator ruling — WP03 SK-08 rerank scope

Date: 2026-09-03. Issued by the operator (Human-in-Charge) via the mission orchestrator.

## What was decided

WP03's first landing (`48d17c872`) made **two** behavioural changes to `route()`:

1. A `canonical_verb`-tier candidate always beats a `domain_keyword`-tier candidate, regardless of
   `routing_priority`.
2. When the verb tier was **empty**, `route()` unconditionally raised `ROUTER_AMBIGUOUS` instead of
   auto-selecting by priority.

**The operator ruled that change #1 stays and change #2 is reverted.** Implemented in `ee522cf8a`.

## Why

Defect-ledger **SK-08** and issue **#3840** both describe a *competition* case — *"one generic domain
keyword outranking the request's own verb"*. Change #1 fixes exactly that. Change #2 altered the
*no-competition* case (a request carrying no canonical verb at all, which previously auto-selected on
a unique domain keyword), which was never the reported defect.

The evidence that #2 over-reached: it broke
`tests/specify_cli/invocation/test_writing_comms_routing.py::test_diagram_as_code_still_routes_to_diagram_daisy`,
a **shipped test that is not stale**. Its own docstring documents the behaviour deliberately —
*"`chart` is a diagram-daisy domain-specific canonical verb (folded into the L3 keyword signal); it is
unique to diagram-daisy across the shipped set."* Under #2 a lone unique keyword became ambiguous, so
requests that route correctly today would have started demanding disambiguation, across every profile.

Two alternatives were considered and rejected:

- **Keep the stricter rule and update the test.** Safer in the abstract (no Op ever opens on a weak
  signal) and aligned with #3840's remark that consumers should apply their own confidence threshold —
  but it changes behaviour far beyond SK-08 and breaks working routing.
- **Reclassify profile-level `collaboration.canonical-verbs` into the verb tier.** Arguably the most
  principled reading, since the tier is named `canonical_verb` and these are declared canonical verbs.
  Rejected because it reverses a deliberate, documented design decision (the fold into the L3 keyword
  signal) and changes tier classification for every shipped profile — bigger than this mission's scope.

## Binding end state

- Canonical-verb tier beats keyword tier when **both** are present. SK-08 fixed; do not weaken.
- An **empty** verb tier restores pre-WP03 behaviour: a unique candidate auto-selects, multiple
  candidates resolve by `routing_priority`, and `ROUTER_AMBIGUOUS` raises only on a genuine tie at top
  priority.
- Profile-level `collaboration.canonical-verbs` remain in the keyword tier.
- `test_diagram_as_code_still_routes_to_diagram_daisy` must pass **unmodified**. It is the acceptance
  signal for this ruling, not an incidental test.

## Consequence that must not be lost

**`spec.md`'s FR-007 still carries the pre-ruling wording** ("whenever zero verb-tier candidates
exist... raise ROUTER_AMBIGUOUS"). The implementer flagged this rather than editing a file outside its
`owned_files` — correct behaviour. The spec now contradicts the shipped code and **must be corrected
before the mission closes**, or the next reader will implement the reverted behaviour from an
authoritative-looking spec. This ruling replaces the acceptance bar for FR-007.
