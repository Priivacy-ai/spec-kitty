# Research: #3685 + #3682 — "Governance at the deciding gate"

**Branch:** `research/3685-3682-enforcement-and-review-evidence` (off `upstream/main` @ 34790048ed, post-#3800)

## The unifying thesis

Both issues are one design principle seen from two layers: **decision-support belongs at the deciding gates (review / accept / post-merge); automation belongs in the automatic phase (implement).**

- **#3685** is the *policy* defect: the doctrine-delivery path pushes "prove/document/gate every step" evidence directives as `required` into the **implement** bundle, with no way for a literal-reader model to discover that the brake/arbiter directives outrank them → mid-mission stalls asking for human approval.
- **#3682** is the *realization* gap: at the actual deciding gates (approve, accept) the evidence is **not** captured — approvals are unbound notes, first-pass approvals write no review-cycle, and the acceptance-matrix is never populated.

So #3685 should **declare** the point-cut policy that #3682 **realizes**. Same theme, different code surfaces and profiles → **two missions under one program**, not one mission.

## #3685 — root cause (architect-alphonso)

**One sentence:** the agent-delivery path (`resolve_context` → `_ActionDoctrineBundle`) is **tension-blind and enforcement-flat** — it traverses only `scope/requires/suggests/vocabulary`, never `in_tension_with`/`reconciles_tension`, and carries `enforcement` as inert text with **no ordering primitive anywhere in the codebase**. The tension-resolution machinery exists but runs only offline (`charter activate` warning + consistency scan), severed from what reaches a dispatched agent.

**Verified:**
- Histogram exact: `packs/built-in/directives/` = **25 required / 6 lenient / 3 advisory**. Brakes are the weak ones: `024-locality-of-change.directive.yaml:7`, `025-boy-scout-rule.directive.yaml:17` = lenient; `reconcile-change-scope-tensions.directive.yaml:15` = advisory; `003-decision-documentation-requirement` = required.
- `Enforcement` is a plain `StrEnum` (`src/charter/offering/directives/models.py:22-27`) — no `__lt__`, no `total_ordering`, no rank map; repo-wide search for a lattice/precedence returns nothing. `pack_validator.py:1376-1385`: "only 'advisory' is recognised today."
- Only **2** `in_tension_with` edges + **3** `reconciles_tension` edges exist (`directive.graph.yaml:117-138, 452-460`); the arbiter (advisory) is ≤ every operand it arbitrates. RECONCILE was an unreachable orphan until `3bcdda344` (08-11).
- `resolve_context` (`src/charter/offering/drg/query.py:111-160`) walks SCOPE/REQUIRES/SUGGESTS/VOCABULARY only — **never** the tension relations. `scan_unreconciled_tensions` is called from just two offline sites (`charter activate` non-blocking warning `activate.py:685-692`; consistency JSON `consistency_check.py:1062`) — never in the delivery path.
- **"static 2026-07-01 snapshot" corrected:** `2026-07-01` is an ADR id, not a snapshot date. The real static artifact is `generated_at: STATIC` graph fragments (`directive.graph.yaml:2-3`), regenerated by `spec-kitty doctrine regen-graph`. The resolver is *not* bypassed; tension resolution is just never invoked at delivery.

**Proposed-fix feasibility:**
1. *"A tiebreaker may never be weaker than what it arbitrates"* — the **data half** (promote RECONCILE's label) is **inert alone** (delivery neither ranks enforcement nor walks `reconciles_tension`). The **real fix** is (a) an ordering primitive on `Enforcement` (`models.py:22`, `functools.total_ordering` + explicit rank), then (b) a structural gate beside T025/T026 in `consistency_check.py`/`drg/validator.py`: "for every `reconciles_tension` R→X, `enforcement(R) ≥ enforcement(X)`". **Hidden coupling:** DRG nodes carry no enforcement (`{urn,kind,label}` only), so the gate must join each edge endpoint back to the directive artifact's enforcement via `DoctrineService` — the main cost. **Deeper fix:** teach `resolve_context` (`query.py:140-151`) to surface `RECONCILES_TENSION`/`IN_TENSION_WITH` so the arbiter is delivered *as* an arbiter.
2. *"Split ceremony by phase"* — lands at the **action→directive scope binding**, specifically DIRECTIVE_003's direct scope edge (`action.graph.yaml:307-309`). **Gotcha:** those scope edges are **generated by the extractor** (`src/charter/offering/drg/migration/extractor.py`), not hand-authored — editing the `.graph.yaml` is reverted on `regen-graph`; the real edit site is the extractor's scope table (or the mission-step contract). **Premise correction:** DIRECTIVE_043 is **not** scoped to implement directly (fragile-transitive via suggested tactics); **003's direct scope edge is the concrete lever.**

## #3682 — root cause (reviewer-renata)  ⚠️ partly landed since rc2

#3682 was filed on 3.2.6**rc2**; substantial machinery has since landed on main (mission `verdict-seam-write-unification-01KZ9Q35` / **#3235**). Current-main state per gap:

- **Gap 1 (unbound approval):** fields are fully plumbed (`StatusEvent.policy_metadata`/`review_ref`, `models.py:355,358`) and passed per-hop, but the **APPROVED hop supplies `None`** — `_mt_hop_policy_metadata` (`tasks_move_task.py:2166-2189`) builds a payload only for CLAIMED + FOR_REVIEW, falls through to `None` for APPROVED; `_binding_role_for_lane` (`:2211-2225`) maps APPROVED→None; a forward approve never rebuilds the plan with a `review_ref` pointer. **Fix seam:** add an APPROVED arm to `_mt_hop_policy_metadata`.
- **Gap 2 (no review-cycle on approve):** the writer is **already symmetric** — `create_rejected_review_cycle(..., verdict="approved")` writes both (`review/cycle.py:999`). The asymmetry is the **caller guard**: `_persist_approved_review_cycle` (`tasks_verdict_persistence.py:790`) returns `None` unless a prior `changes_requested` verdict exists (`:852-853`), so first-pass approvals no-op. **Fix seam:** relax that one guard so first-pass approve also authors an `approved` cycle via the existing write/commit/durability path.
- **Gap 3 (matrix never populated):** producer (scaffold at finalize, `mission_finalize.py:2353`), populator (a *separate manual* command `agent mission acceptance-verdict`), and consumer (`accept`) are disconnected. `accept`'s gate (`gates_core.py:450-571`) now **recomputes + blocks on `pending`** (post-#3076) but **never populates rows from recorded evidence**. Historical pending matrices predate #3076 + the `cannot_evaluate` skip + `--allow-fail`. **Re-derived count (this snapshot):** 255 matrices, **103 pending**, 40 merged, 11 with an explicit `accept_commit` — shape confirmed; the exact "95/237" is a different/earlier snapshot, don't quote it. **Fix seam:** `accept` auto-populates criterion rows from status events + review-cycle artifacts before recomputing (or close the skip/allow-fail escape for the matrix).

**#3685 linkage:** all three #3682 fixes land at the deciding gates (approve, accept), **not** the implement loop — they are **symmetry completions of an existing gate** (the reject/claim half already has the machinery), so they do *not* re-introduce #3685's implement-phase ceremony. **Discipline:** auto-author the approval cycle/matrix *from the decision already made* (never a hand-filled form) — otherwise it becomes the exact friction #3685 warns against.
