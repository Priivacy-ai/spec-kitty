Three required answers for spec_review

Who calls it?

The root registry calls the thin P21 CLI leaf. P21 calls P28. P28 alone sequences preflight, prompt, runner, parser and storage. P29 alone enters the mission-runtime placement boundary.

What does it touch?

It reads only the selected canonical spec.md. After an actual external start, it may exclusively create one reviews/spec-review-<run-id>.yaml. It does not change Mission/WP lifecycle, existing review, ProfileInvocationExecutor or credential storage.

Which tests cover it?

tests/specify_cli/spec_review/ covers each module; integration and mission-runtime suites cover command-to-artifact flow and PRIMARY placement; architectural gates enforce consent-bound egress; Windows atomic-write tests are explicitly routed to windows_ci. Live model execution remains opt-in and is not part of normal CI.
